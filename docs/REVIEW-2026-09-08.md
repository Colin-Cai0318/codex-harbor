# Weekly reset Luna message

When Harbor has no work to send after the weekly allowance resets, users can now
enable an independent dashboard switch to send one short Luna message. The default
is off. The fixed model is `gpt-5.6-luna`, reasoning `low`; reserve and primary task
models are unchanged.

The scheduler observes weekly reset boundaries from fresh quota snapshots. Future
estimate revisions do not trigger sends. Once the recorded boundary passes, both
primary and weekly availability are required. Offline restarts retain the boundary;
disabling the feature discards the pending observation. Pool freeze/pause does not
disable this separate, explicitly opted-in action.

SQLite settings and a primary key on the UTC reset time prevent concurrent or
restarted daemons from repeating an attempt. The durable claim precedes inference.
Unknown delivery after cancellation, crash, or timeout is not retried automatically.
This favors avoiding duplicate charges over an unsupported exactly-once guarantee.
The read-only conversation runs in a dedicated data directory and its App Server
process closes on every exit. The request is bounded to 90 seconds.

The dashboard and `GET /api/weekly-ping` expose the last attempt, errors, and the next
reset time observed after a successful message. `PATCH /api/weekly-ping` accepts
`{"enabled": true}` or `false`. A completed message is not represented as proof that
the server started a new weekly timer. The
[official pricing documentation](https://learn.chatgpt.com/zh-Hans/docs/pricing)
does not establish that guarantee.

Validation covers default-off behavior, future revisions, crossing a boundary,
quota unavailability, missing telemetry, null reset timestamps, restart/toggle
deduplication, concurrency, uncertain failures, cancellation, API persistence,
frozen scheduling, and read-only model selection/client cleanup. A real Luna/low
request returned exactly `OK`, without tool calls; an independent client then
resumed its thread successfully. No real weekly reset was induced or awaited.

Local regression: 117 tests passed. Ruff, compilation, and dashboard JavaScript
syntax checks passed. A headless Edge test toggled the switch on, reloaded to
verify persistence, and toggled it off without browser errors. Desktop and narrow
viewport screenshots were inspected; both switch labels remain visible on mobile.
