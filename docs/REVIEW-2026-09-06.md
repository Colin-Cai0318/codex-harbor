# Maintenance review / 维护审查 — 2026-09-06

Reviewed the checkout based on `7794498`, with emphasis on concurrent completion,
failure cleanup, task admission and public source publication.

Local verification: **84 tests passed**, **87% statement coverage** on Windows
with Python 3.14.6; `compileall` passed. The 416 warnings originate from dependency
deprecations. Reproduce with `uv run pytest -q --cov=codex_harbor`.

| 问题 / Finding | 修复 / Result |
|---|---|
| 等待某个任务会丢掉其他任务已缓存的完成通知 | 保留不匹配通知；到达中的通知按等待者条件分发；连续完成两个任务不会互相吞掉通知 |
| 已交付的完成通知还会留在缓存里 | 仅缓存没有接收者的通知，避免同一个完成结果被重复消费 |
| App Server 断线后，Turn 等待可能持续到一小时超时 | EOF 和主动关闭立即向等待者传播错误；初始化失败关闭客户端 |
| 合法 JSON 数组/null 会使读取循环报错 | 忽略非对象消息，继续读取后续有效响应 |
| Worker 外围异常只记录日志，任务可能永久 RUNNING | 已结束且抛出异常的 Worker 将活动任务标记 BLOCKED，清除领取状态，允许用户检查后重试 |
| Worker ID 根据活动数量生成，会重用仍在运行的编号 | 使用 UUID，回归测试覆盖前面的任务先结束、后续任务补位 |
| 非法 backend、零次重试可以进入队列 | 在持久化入口验证，API 返回 409，避免坏任务进入调度循环 |
| 对话创建响应缺少 ID 时返回不明确的 500 | 上游错误返回 502，并删除本轮未成功绑定对话的本地任务 |
| resume 的额度、认证、网络错误被当成 session 不可用 | 保留原 session，进入额度等待、阻塞或延迟重试；不因这些错误 fork 对话 |

Regression tests cover buffered out-of-order completions, back-to-back concurrent
completions, no duplicate delivery, EOF/close wakeup, initialization cleanup,
worker identity reuse, crash state cleanup and invalid admission. Tests use fakes
and temporary databases/repositories without submitting model turns.

本轮使用模拟运行时和临时数据库/仓库，不提交实际模型 Turn。Git 跟踪文件及历史
文件列表已检查，常见私钥和 token 格式扫描未发现匹配；这不是完整的外部安全审计。

## Remaining boundaries / 仍需改进

- API remains local and unauthenticated; public source publication does not make
  Harbor suitable for public-network deployment. See [SECURITY.md](../SECURITY.md).
- Long-running streaming notification backlog, graceful shutdown during an active
  edit, process restart/reboot recovery and multi-daemon coordination still need
  dedicated soak testing and design work.
- Live quota reset and desktop-version interoperability require real environment
  qualification. Automated state-machine tests cannot establish these guarantees.
- Error classification still uses text markers; additional protocol-specific
  structured error variants need qualification after App Server upgrades.

此前 86% 为语句覆盖率，不代表所有竞态和系统恢复场景已验证。本次审查再次发现了
高覆盖率下仍会遗漏的并发缺陷；后续应继续以场景和持久化结果为验收标准。
