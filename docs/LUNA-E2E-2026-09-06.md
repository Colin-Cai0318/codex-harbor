## Failure found / 发现并修复

The first coding preflight failed before creating a Turn because the live quota
endpoint returned `error sending request for url`. The original classifier did
not recognize that transport wording, so a similar error during session resume
could enter the fork fallback instead of delayed retry.

Network classification now includes this wording, connection refusal, broken
pipes and App Server disconnection. Regression tests prove that resume errors
with the observed wording and stdout closure keep the original session, enter
`RETRY_WAIT`, and never fork/start another Thread. The live test preflight also
retries quota reads at most three times. A subsequent coding run passed.

## Reproduce / 复现

Install development dependencies with `uv sync --extra dev`. These scripts use
your signed-in Codex account. Use a different, nonexistent output directory for
each run; existing evidence is not overwritten.

```powershell
uv run pytest -q --cov=codex_harbor
uv run python tools/luna_e2e.py --output .harbor/luna-preflight-new
uv run python tools/luna_e2e.py --execute --output .harbor/luna-flow-new
uv run python tools/luna_e2e.py --execute --coding-only --output .harbor/luna-code-new
```

`--execute` submits live model turns. The flow run uses seven Turns; the coding
run permits at most two attempts. Both require an existing Codex Project matching
the checkout and an existing Git test workspace (override with `--workspace`).

Local raw evidence remains Git-ignored under `.harbor/luna-full-20260906/` and
`.harbor/luna-code-retry-20260906/`; the failed preflight was retained under
`.harbor/luna-code-20260906/`. Evidence includes SQLite attempts and JSON results.
The generated test module remains in the existing fixture for inspection.
