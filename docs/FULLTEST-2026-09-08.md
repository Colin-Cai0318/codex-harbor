# Full regression and fixes — 2026-09-08

Baseline: `5ffc2a1`. The initial 117-test suite passed with 88% coverage, but
targeted regression and real Luna execution exposed issues beyond that suite.

## Fixes

- Weekly ping awaited model inference inside the scheduler tick, delaying task
  admission and cancellation for up to 90 seconds. A dedicated, single background
  task now handles sending; shutdown cancels and joins it. A stalled sender test
  verifies subsequent scheduler ticks and shutdown remain responsive.
- Actual quota snapshots returned weekly reset epochs `1789402488` and
  `1789402489` for the same window. Exact-timestamp deduplication could resend
  after expiry or toggling the feature. Claims now check a five-minute neighborhood
  under the same SQLite write transaction; small revisions do not advance the
  pending cycle. A later weekly boundary can still send normally.
- A slightly advanced or already-expired timestamp could be displayed as the
  next weekly reset. Confirmation now requires a future timestamp beyond the
  jitter tolerance. New regression tests reproduced both timestamp defects before
  the fixes.
- The live Luna script read `root_thread_id` before the worker created its thread,
  unintentionally starting a new conversation in its continuation phase. It now
  obtains the persisted ID after execution and asserts identity after continuation.
  Workers use the daemon's separate-client ownership behavior.
- Twelve existing lint issues were resolved: imports, shared fixture annotation,
  blocking subprocess use in an async test, overly broad exception assertions,
  and loop variable binding in the live runner. CI now checks the relevant rules.
  Ordinary Luna/xhigh evidence is explicitly named separately from native Reserve.

## Validation

- **121 tests passed**, **88%** overall coverage; weekly ping **95%**, scheduler
  **94%**. Coverage measures automated tests, not the separate live runs.
- Full configured Ruff scan, JavaScript syntax, Python compilation, source archive
  and wheel builds passed.
- Real Luna/low: cross-process context recall; acceptance failure, retry and
  dependent-task release; two parallel conversations; code generation with a real
  Python acceptance command. All passed after the runner correction.
- Three real turns in one conversation: Luna low → xhigh → low, context preserved,
  original effort restored, and independent-client resume after worker exit.
- Headless Edge: switch on/off and reload persistence, desktop/narrow rendering,
  no JavaScript page errors, using isolated storage and an ephemeral local port.
- Local Harbor was found stopped (port 8765 refused connections, no daemon process).
  Its database was backed up and passed `PRAGMA integrity_check`; all six historical
  tasks were terminal. The new daemon started successfully, with weekly ping still
  off and Luna Reserve still on. No existing process needed to be terminated.

Evidence is kept locally under ignored `.harbor/fulltest-20260908-*`,
`.harbor/fulltest-coverage.json`, and `.harbor/weekly-ping-browser/`.
The first failed live run is retained alongside the successful rerun.

Real weekly rollover, 5-hour quota depletion/reset, native `gpt-reserve` billing,

and ordinary Luna/xhigh turns do not establish those behaviors.
